## 第 1 题（C-2）：付费操作预算上限填多少？

超出这个数的任何花钱操作，智能体必须先停下来上奏，不许自己刷卡。

- **A. 0 元（一分钱都要先问）** — 最安全，但凡是付费 API 调用都会打断你审批，任务节奏慢。
- **B. 单任务 ≤ 10 美元（推荐）** — 日常 LLM 调用、小额云资源不打扰你；大额自动拦下。适合大多数开发任务。
- **C. 单任务 ≤ 100 美元** — 适合频繁跑大模型训练/批量推理的项目；代价是误烧钱上限也高。
- **D. 其他** — 自己写一个数（可按「每任务」或「每月」计），宰相会回炉确认口径。

把选定的数字（含币种与计费口径）直接替换 C-2 条款中的 `[预算：____]`。

## 第 2 题（C-6）：要不要加项目自定义红线？

C-1~C-5 是通用红线；C-6 留给你这个项目特有的「碰了就停」事项。

- **A. 暂不增补（推荐）** — 先用通用五条跑一个月，发现漏洞再补；条款写「暂无，留待增补」。
- **B. 禁改指定目录/文件** — 例如「不得改动 `infra/`、CI 配置、数据库迁移文件」；防止智能体好心帮倒忙。
- **C. 禁碰指定外部系统** — 例如「不得调用生产数据库、不得向真实用户发通知」；适合已有线上用户的项目。
- **D. 其他** — 用一句话描述你的红线，宰相帮你改写成「违反即停」的条款句式。

选 B/C 时，把具体目录名/系统名写进 C-6，越具体越好；模糊红线等于没有红线。

## 第 3 题（G-4）：任务验收清单用什么方式生成？

G-4 是「每个任务开工前」都要重填的活条款，这里定的是**填写流程**，不是某次的内容。

- **A. 宰相起草、皇帝逐条确认（推荐）** — 派任务时宰相按 G-1/G-2 拟出产物清单和验收方式，你逐条勾选通过；省你的脑力又留了否决权。
- **B. 皇帝亲自写** — 你在派任务的消息里直接写死清单；最可控，但每次都要多花你几分钟。
- **C. 走 spec-kit 流程** — 已装 spec-kit 的项目用 `/speckit.clarify → specify` 产出的 spec 直接充当 G-4；与现有工作流无缝。
- **D. 其他** — 描述你想要的流程，宰相回炉出选项。

把选定流程写进 G-4，例如：「G-4：每任务由宰相起草清单，经皇帝逐条确认后生效」。

## 第 4 题（版本记录）：初版签署行怎么落笔？

版本记录是宪法生效的凭证；没签署的宪法只是草稿。

- **A. 今天签、批准人写你的常用名/ID（推荐）** — 日期填今天（YYYY-MM-DD），批准人填你的 GitHub ID 或称呼；立即生效，最简单。
- **B. 先试运行一周再签** — 版本号标 `0.1.0-draft`，一周后无异议改正式；谨慎，但试运行期条款约束力存疑。
- **C. 其他** — 例如需要多人会签、或想改初始版本号，描述后宰相回炉出选项。

落笔示例：`| 0.1.0 | 2026-07-30 | 初版签署 | wookat |`（替换表末行的两个 `____`）。

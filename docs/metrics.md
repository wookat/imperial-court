# 阶段 0 度量口径与杀死条件

数据源：`memory/decree_log.md`（跑满一个月或 ≥15 个真实任务后结算）。

## 指标

| 指标 | 计算 | 含义 |
|---|---|---|
| 封驳触发率 | 封驳次数 / 指令总数 | 制度是否被用到 |
| 封驳采纳率 | 裁决为"采纳替代/收回" / 封驳次数 | 谏言质量（皇帝认不认） |
| Other 占比 | 点选"其他" / 选择题总数 | 选项生成质量 |
| 上奏密度 | 上奏次数 / 任务数 | "免打扰"程度 |
| 返工率 | 验收打回次数 / 委派次数 | 契约验收有效性 |

## 判定（事先约定，防自我欺骗）

- **继续（进入阶段 1）**：封驳月触发 ≥ 3 次且采纳率 ≥ 30%；Other 占比 < 40%。
- **修 prompt 再跑**：Other 占比 40–60%，或封驳全被"坚持原令"驳回 → 选项/谏言质量问题，先迭代 Skill 文案。
- **杀死**：封驳月触发 < 3 次（伪需求）且上奏密度也低（现有平台已够用），止损。

注意：交互体验的主观好坏**不作为**证伪依据（宿主 UI 天花板会产生假阴性），只看上述行为数据。
